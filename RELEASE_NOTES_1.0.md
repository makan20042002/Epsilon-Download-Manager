# Epsilon Download Manager 1.0.0 — release notes

**Version numbering reset to 1.0.0 for this first public release under the Epsilon name.** The feature set below is everything that was built and tested as "16.0.0" internally during development (BitTorrent, the browser extensions, the rename itself, and everything else on this page) - nothing was removed or changed for the renumbering, only the version string. There is no separate 1.0.0 changelog to go with an earlier 16.0.0 one; this page **is** that changelog, just under the version number this app is actually launching as.

**Renamed from Makan Download Manager to Epsilon Download Manager** partway through this release - every user-visible name, the About window, the app icon, both browser extensions, and the installer now say Epsilon. A few internal, non-visible identifiers were deliberately left alone (the `MakanDownloadManager` C# namespace/project files, the built `MakanDownloadManager.exe` filename, and the installer's AppId GUID) since renaming those is a much larger, separate, higher-risk change than a display-name/branding update, and nothing about them is ever shown to a user. The Firefox extension's internal add-on ID also changed (to `epsilon-download-manager@makanlab.tech`) - if it was already submitted to addons.mozilla.org for signing under the old ID, that submission needs to be redone with the new one, since Mozilla ties a signature permanently to whatever ID was submitted.

16.0.0 adds full BitTorrent support, a global speed limiter in the main window (like IDM's), and a redesigned browser-extension menu with a dark "premium" style and a lighter, softer light style. Everything from 15.1.0 is unchanged unless listed below.

## Added
- **The download progress window has been completely redesigned** in the "Epsilon" brand look from the UI design kit (custom borderless title bar with a live connection-count pill, a glowing gradient progress bar, a redesigned two-column connection list with a *live per-connection speed* that wasn't shown before, and the Speed Limiter / On Completion settings reorganised into a chips-and-cards layout instead of tabs). This window always uses the Epsilon dark palette regardless of which of the four app themes is active, matching the design kit's own intent for it to be a consistent "signature" look. Verified against the app's own automated checks (every new piece of text has a Persian translation, every event handler and named element in the new XAML resolves correctly) and the full test suite - no regressions.
- **BitTorrent client**, written from the protocol specifications (no third-party torrent library): magnet links and `.torrent` files, DHT and peer exchange so a magnet with no working tracker still finds peers, HTTP and UDP tracker announces, rarest-first piece selection with an endgame mode for the last pieces, per-file priority (Skip / Normal / High), resume across restarts (the saved position is only trusted if the files on disk have not changed since), and seeding with a configurable share-ratio or time limit.
  - **Automatic port forwarding (UPnP, then NAT-PMP fallback)**, written from the specifications the same way the rest of the torrent engine was: on startup, Makan asks the router to forward its listening port so peers behind a typical home NAT can connect in rather than only ever connecting out - previously the biggest documented gap in real-world torrent connectivity. Entirely best-effort: a router that answers neither protocol (or none at all, e.g. no network) leaves torrents working exactly as before. The lease is short (30 minutes) and renews itself, and is removed again on a clean shutdown.
  - New **torrent details window** (double-click a torrent in the list, even after it shows *Complete* since it may still be seeding): live speed, peer count, seed count, ratio, a **Files** tab with the priority picker, a **Peers** tab, and a **Trackers** tab. Per-torrent download/upload limits, Pause/Resume, Open folder, Copy magnet link, and Remove (with or without deleting the files).
  - New **Add Torrent** button (toolbar and menu): paste a magnet link, or browse for a `.torrent` file — no browser needed.
  - New **BitTorrent** tab in Options: listening port (with a "Random port" button), DHT and peer-exchange toggles, upload slots and max peers per torrent, **separate** global torrent download and upload limits (independent of the toolbar's Speed Limiter, which only covers ordinary downloads), seeding controls, and a **schedule**: separate allowed hours for downloading and for seeding, since the two are different activities often wanted at different times (e.g. seed only overnight). A torrent outside its hours simply pauses and resumes itself once its hours come back around; a torrent paused by hand stays paused regardless of the schedule.
  - New **Torrents** entry in the sidebar to see just the torrents among your downloads, without leaving the same list.
  - **A finished torrent does not seed by default.** It just stops - nothing uploads until you open its details window and choose Resume, or turn "Keep sharing a torrent after it finishes downloading" on in Options > BitTorrent for every torrent going forward.
  - **Global download/upload limits, both global and per torrent**, live-adjustable while a torrent runs.
  - Windows registers Makan as the handler for `magnet:` links and `.torrent` files during install, so opening either one outside the browser (another program, a file already on disk) launches Makan directly - or, if Makan is already running, hands it to that copy instead of starting a second one. Windows will ask you to confirm this the first time, which is normal.
  - The browser extension now recognises a clicked magnet link on a page and sends it straight to Makan (a small toast confirms it), the same way a captured HTTP download already worked; Ctrl/Shift/Cmd/Alt-click still lets the browser handle it. Right-click → "Download link with Makan" on a magnet link, and a `.torrent` file downloaded over plain HTTP, already worked and are unchanged.
- **Global Speed Limiter** in the main window's toolbar (Options > Connection had a setting for this before; now it is one click away, like IDM): a popup with a slider, an exact KB/s box, and the existing bandwidth-profile presets (Unlimited / Gaming / Work / Night). The limit applies to ordinary downloads and, when BitTorrent is running, to torrent downloads too.
- **Browser extension redesign**: the "Download this video" bar and menu shown on pages now has a dark, compact "premium" look and a softer light look (replacing the previous plain white one), switching automatically with the browser's colour scheme or a manual Auto/Dark/Light choice added to the toolbar popup under "Appearance". Both looks share one CSS-variable stylesheet, so the two are always visually consistent and the Chrome/Edge and Firefox copies stay byte-identical.
- **New brand identity**: replaced the old "blue square + arrow" icon with the new Makan Download Manager logo (the app, both browser extension icons, and the installer all use it now). Dark mode's background moved from a blue-grey to the true navy behind the new logo, so the app and the brand artwork now actually match; light mode was left alone since its accent blue already was the brand's exact blue. Green is now used consistently for "torrent" across the app and the extension (the toolbar's Add Torrent icon, the extension's on-page button) rather than the unrelated orange the extension used before - matching the brand note that green should mean torrent/connected/success and nothing else, so it doesn't turn into decoration. Every new colour was checked against the same automated readability tests as the rest of the theme (WCAG-style contrast ratios) and all pass.

## Fixed (found while building the above)
- **Force Download didn't actually force anything if MaxActive (the "how many downloads at once" limit, default 4) was already full** - a 5th torrent (or a 3rd, a 2nd, whatever the limit is set to) stayed stuck in Queued even after clicking Force Download, since that only ever bypassed the download/seed *schedule*, never the overall active-downloads limit that was actually the thing blocking it. This is likely what "only 4 download, and Force Start doesn't work" was - torrents go through the exact same MaxActive gate as ordinary downloads (they're added the same way), and Force Download only covered half of what could block one. Fixed: Force Download now bypasses MaxActive too, exactly like uTorrent's/qBittorrent's Force Start does. Added a regression test that reproduces this precisely (fill MaxActive with torrents, add one more, confirm it's stuck, Force Download it, confirm it actually starts without pausing the others).
- **Resuming one selected download that belonged to a queue resumed the whole queue instead** - clicking Resume on a single paused file could start three or four others alongside it, up to that queue's "download N at once" setting. The Resume button was calling "start this queue" internally whenever the selected file happened to be a queue member, instead of just resuming that one file. Fixed: Resume now always resumes exactly what's selected, never more; starting a whole queue on purpose (Start Queue, or the sidebar's per-queue button) is unaffected and still works the same way. Added a regression test that reproduces the original bug (four queued files, resume one, four used to start) to make sure this can't come back silently.
- A torrent's list of already-tried peers was never cleared on Pause → Resume, so a resumed torrent could sit with zero peers even though its trackers were handing back the same ones. Fixed by resetting that state on every (re)start.
- Resume trusted a saved bitfield within a 2-second time tolerance on the files' modified time; a file changed moments after saving could slip through undetected. Now the modified time must match exactly.
- Re-adding a magnet link or `.torrent` address that had already finished and was seeding created a second, separate list entry silently sharing the same underlying torrent session as the first — a real correctness risk (both entries could pause/remove/resume it independently). Duplicate detection for torrents now also matches a finished-and-seeding entry, not only an actively downloading one.
- The website address was `makanlab.tech.in` in several places (Branding.cs, the main window, both extension popups, the installer); corrected to `makanlab.tech`.
- There was no way to add a magnet link or a `.torrent` file from inside the app itself (only from the browser) — added an **Add Torrent** toolbar button and menu item (paste a magnet link, or browse for a `.torrent` file).
- Clicking a `.torrent` file or a magnet link anywhere outside the browser (a download from another program, a file already saved to disk) had nowhere to go. Makan now registers itself as a handler for both during install, so they open directly in Makan; if Makan is already running, the link is handed to that instance instead of starting a second one.
- **Dark mode's text was unreadable.** Rebuilt dark mode from VS Code's actual "Dark+" colours rather than hand-picking values; verified with the app's own automated contrast checks (both themes pass every check, not just eyeballed). Along the way, found and fixed a real design conflict: one blue was being used both as button-fill (needing to be dark enough for white text) and as icon/text colour on cards (needing to be light enough to read) - no single colour can do both well against this dark a background, so `Accent` (icon/text) and `AccentDark` (button/checkbox/radio fill) are now properly separate roles, consistently applied across every dialog.
- **The priority dropdown (Skip/Normal/High) in a torrent's Files tab would close before you could choose anything.** The details window refreshes its file list every 700ms; that refresh was rebuilding the whole list - including any dropdown you had open - out from under you. Now paused while the dropdown is open.
- The "Q" column in the main list didn't say what it meant. Now says "Queue" and shows the actual queue name instead of a bare checkmark.
- Removed the "Makan Lab" / "makanlab.tech" branding from the main screen (top bar and status bar) and replaced the plain About message box with a proper **About** window (Help menu): version, creator, a clickable website link, and a clickable email link.
- **New: one-click playlist download.** Adding a YouTube (or other yt-dlp-supported) playlist link now offers to download every video at one chosen quality, instead of only ever grabbing the first video. A normal single-video link is unaffected.
- **The Persian translation mistranslated "Makan" as "مکان" (Persian for "place/location") everywhere** - the main window title, the About window, the tray tooltip, dozens of settings and messages - instead of the correct transliteration "ماکان". Fixed in both the desktop app and the browser extension (67 occurrences total); one legitimate, unrelated word that happens to contain the same letters ("امکان", meaning "possibility") was correctly left alone.
- The right-click "Download link with Makan" / "Download all links with Makan" / "Open Makan Download Manager" browser-extension menu items are now labelled "Download with MDM" / "Download all links with MDM" / "Open MDM" for brevity, in English and Persian.
- **First-run checklist**: shown once after installing (Help > Getting started to see it again) - whether the browser extension is connected, whether the video-download tools are installed, and the current download folder, each with a one-click fix.
- **Toolbar decluttering**: the eight least-used buttons (Stop All, Delete Completed, Start/Stop Queue, Scheduler, Intelligent Center, Grabber, Theme) moved into a new "More" button, rather than sitting in the main row alongside Add / Add Torrent / Resume / Stop / Delete / Speed Limiter / Options.
- **New: play a video/audio file while it is still downloading** ("Play (downloaded part)" on the right-click menu). Makan pre-allocates the whole file up front and fills it in out of order, so the file on disk is not safe to open directly (a player could seek past what has actually arrived); this instead works out exactly how many bytes from the very start are gap-free and copies just that safe portion to a temporary file before handing it to the default player.
- **New: a remote status page** (Options > Remote) - the realistic alternative to a native Android app. An opt-in, token-protected local web page a phone's browser can open on the same Wi-Fi/network to see progress and add a new download, without installing anything. Plain HTTP, meant for a home network only.
- **New: Ctrl (or Cmd on Mac) + click on a download link now lets the browser keep it**, the same way Alt + click already did - previously this only worked for magnet links, not ordinary downloads.
- **Makan's window now comes to the front when a new download arrives** (a browser capture, a magnet link opened outside the browser, etc.), instead of only ever showing the small per-download progress popup. Off switch in Options > Downloads if preferred.
- **New, opt-in: a speed boost that pauses Windows Update and similar background services** (BITS, Delivery Optimization) while something is actively downloading, and un-pauses them the moment it isn't (Options > Connection). Needs administrator rights, which Makan does not request on its own; without them it says so plainly rather than silently doing nothing. **Important limit, stated plainly**: this only pauses those specific Windows services - genuinely throttling every other program's network use (the way NetBalancer/NetLimiter do) needs a custom kernel-level network filter driver, a fundamentally different and much larger project than this app; that is not what this feature does.
- **New: Force Download for torrents** (right-click a torrent > Force Download), the same idea as uTorrent's/qBittorrent's "Force Start" - keeps that one torrent running regardless of the download/seed schedule, until switched off again.
- **New: per-queue Start/Stop** - a small ▶/⏸ button next to each queue's name in the sidebar, instead of only picking a queue from the Start Queue / Stop Queue list.
- **New: a separate save folder for torrents** (Options > Save to > Torrents) - empty means "same as everything else" (unchanged default); set it once and every new torrent (the app, the browser, a magnet/`.torrent` file opened from outside, or the phone remote page) uses it. Torrents already added keep their existing folder.
- **New theme: Orange / Bone-White** - a third theme alongside Light and Dark (Light and Dark are unchanged), picked from the same "More" menu the theme toggle used to live in, now a proper picker with all three options and a checkmark showing which is active.
- **New: live download/upload speed on the tray icon itself** - the same idea NetBalancer's tray icon uses: while something is actively transferring, the icon is redrawn to show the current numbers (download above, upload below) instead of the plain logo, so activity is visible without opening the window. Goes back to the normal icon once everything is idle. **On the "put it on the taskbar itself" idea**: there is no supported way for an app to add a persistent element to the Windows taskbar outside the system tray/notification area - the tray icon above *is* that feature, in the only place it can actually live (the same place NetBalancer's own version lives).

## Notes
- **Torrent upload/download speed limits were checked and do genuinely work** - both the global limit (Options > BitTorrent) and the per-torrent one (the torrent details window's footer) are backed by tests that measure real, timed throughput against the set limit, not just that the setting can be saved. Traced the full chain by hand too: the per-torrent boxes write to the same field the engine's rate limiter reads, and the global boxes are applied both at startup and live when changed in Options.
- **The About window's email is a placeholder** (`contact@makanlab.tech` in `Branding.cs`) — replace it with the real address before shipping; a wrong email is worse than none.
- BitTorrent implements the core protocol (BEP 3, 5, 9, 10, 11, 12, 15, 23) and automatic port forwarding (UPnP/NAT-PMP), but not protocol encryption, µTP, or web seeds; peers behind an ISP that throttles unencrypted torrent traffic, or a NAT that neither UPnP nor NAT-PMP can open, may still connect poorly.
- Adding a torrent (from the app, the browser, or by opening a magnet link/`.torrent` file) always starts it right away; it does not go through the "Start or Later?" prompt that ordinary HTTP downloads get, even when that option is on.
- Windows asks the person to confirm the choice the first time a `magnet:` link or `.torrent` file is opened after installing (its own protection against a program silently taking over a file type) - this is expected and cannot be skipped by the installer.
- As with 15.1.0, WPF/XAML compilation, DPAPI/SQLite tests, and the actual Inno Setup build could not be run in the environment this was built in; only source-level validation (`tools/validate-source.js`) and the cross-platform engine/extension test suites could be run. Please run `build-release.ps1` then `build-installer.ps1` on Windows and report any errors.
- **No native Android app** - a genuinely separate project (different language, different SDK) rather than a feature of this codebase; the remote status page above is the realistic middle ground.
- The remote status page's speed-boost and streaming-while-downloading features could only be tested for their own logic (mock services, a real HTTP server, a hand-built partial file) - not against Windows' actual Update/BITS/Delivery Optimization services or a real media player, which this environment cannot run.
- The tray icon's live speed display (and every other MainWindow.xaml.cs / SettingsWindow.xaml.cs change this release) could only be checked by careful manual review, not a compiler - the WPF/WinForms parts of this project have never once compiled in this environment. Please watch the sidebar's queue toggles, the tray icon during an active download, and the three-way theme picker specifically when you first run this build.
